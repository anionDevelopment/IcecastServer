# Release notes

## Changes

- Updated to new structure.
- Non-code updates.
- The image is buildable again: the base-image is now stated as build-argument (which is what the build fills with the address from the image-definition of the repository) instead of being a literal in the dockerfile
- Removed the obsolete prefix "GRYVA" of the former product-name. It was left in the copy-instruction of the dockerfile (which is what broke the build), in the example-task, in the workspace-file, in both readmes, in the reference and in the security.txt
- The scripts of the codeunit now use the current api of ScriptCollection (the api "TasksForCommonProjectStructure" which they used does not exist anymore, so they were not runnable)
- The health-check of the image is now used and the label-format of the dockerfile is the current one
- The icecast-version which is installed in the image is pinned now: it is defined in `IcecastServer/Other/Resources/Dependencies/Icecast/Version.txt`, the build reads it from there and passes it to the dockerfile as build-argument `icecast_version`. Before that the dockerfile installed whatever `apk add icecast` resolved to at build-time, so the content of the image was not reproducible
- `UpdateDependencies.py` of the codeunit is implemented now (it only contained a TODO before): it determines the latest icecast-version which the alpine-image declared in `.ScriptCollection/OCIImages/ImageDefinition.csv` provides and writes it into the version-file
